## 구성과 비교의 한계

- GPT: GPT-5.4로 대본·Manim 코드·초기 화면 검토·원문 대조. 편집 후 화면은 별도로 Sonnet 5.5에서도 재검토했다. 처음 두 대본 요청은 medium reasoning에서 출력 한도에 도달했고, 이후 low reasoning으로 변경했다.
- Claude: Opus 5.5로 대본·코드 생성, Sonnet 5.5로 화면 검토·원문 대조. 비스트리밍 요청의 시간 초과 뒤 스트리밍으로 변경했다.
- 공통: 제공 ZIP의 사실 추출 결과를 재사용했다. PDF를 읽는 앞 단계를 이번 비용에 포함하지 않는다. TTS·ASR·FFmpeg는 로컬, 생성된 Manim 코드는 네트워크 없는 Docker Desktop 컨테이너에서만 실행했다.
- 각 job은 $3.50 상한을 적용한다. timeout으로 usage가 돌아오지 않은 요청은 예약액을 유지한다. 아래 비용은 API가 반환한 토큰 사용량과 설정 가격표로 계산한 **추정치**이며 청구서가 아니다.
- 두 작업은 병행했지만 Windows bridge의 Docker 렌더는 직렬 처리했다. 경과 시간에는 렌더 대기, 실패·재시도, 수동 분석·수정 시간이 포함된다. 순수 모델 생성 속도의 벤치마크가 아니다.

## 실제로 발견하고 고친 것

1. GPT 대본이 반복해서 목표 길이를 넘겼다. 완성된 대본에서 중복 배경·아웃트로 장면을 제거하고 영문/수치 TTS 발음을 정규화했다. 일부 낮은 음성 인식 일치율 문장은 뜻을 유지해 다시 읽었다.
2. 두 모델 모두 처음에는 배치 오류가 있었다. Claude는 제한된 자동 수정으로 미리보기 검토를 통과했다. GPT는 자동 수정 뒤에도 겹침·작은 글자가 남아 헤더·라벨 위치와 마지막 결론 카드를 수동 보완했다. `editorial-layout-changes.json`과 이전 QA 기록을 보존한다.
3. 미리보기는 첫/중간/마지막 문장 끝의 세 프레임을 제공하는데, 기존 검토 문구는 모든 문장을 보여준다고 설명했다. 검토 프롬프트를 실제 샘플링과 맞추고 이미지 폭을 270→360px로 높였다. 이전 오탐에 사용된 호출 비용도 집계에 포함한다.
4. Claude 첫 문장의 “생성 모델” 표현을 “flow matching 모델”로 좁히고 음성을 다시 만들었다. GPT 실험 그래프의 움직이는 p 라벨은 논문에 없는 중간 실험값처럼 읽히지 않도록 실제 표의 조건만 표시한다.
5. 공통 facts에 빠져 있던 원문의 평균 속도 정의(3쪽 §2)와 발산 반례 미분식(18쪽 B.4)을 실제 원문 인용으로 추가했다. p<0.5 스칼라 개형의 무계성은 Eq. (20)의 **대수적 귀결**로 구분해 기록했다. 명시적으로 표시한 개형 파라미터를 실험 측정값으로 오인하지 않도록 judge 지침을 명확히 했다.

따라서 최종 두 영상은 **각 모델의 생성물 + 검토·수정 작업**이다. 아무 개입 없이 한 번 호출한 결과나 공정한 모델 우열 실험으로 해석하면 안 된다. 원본보다 품질이 좋다는 주장도 하지 않는다. 원본, GPT v2, Claude v2를 같은 논문 카드에서 직접 비교하는 것이 목적이다.

## 증거 파일

공급자별 `summary.json`은 실측 길이, 사용량 기반 비용, 불확실 예약액, API 응답 대기, 전체 경과 시간, 단계별 시간을 담는다. `budget.json`은 실패·재시도를 포함한 요청 기록이다. `validation.json`, `qa.json`, `render_report.json`, `storyboard.json`, `claims_timeline.json`, `captions.srt`를 함께 보관한다. 원문 대조는 추출 facts 기반 자동 검토이므로 인간의 학술 검증을 대체하지 않는다.
